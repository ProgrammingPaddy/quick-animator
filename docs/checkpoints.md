# Checkpoints

The build order. One checkpoint at a time. Nothing from a later checkpoint is started early,
even when it is easy. Each checkpoint ends with the owner using it by hand and a pass on feel.
Requirement numbers refer to `requirements.md`; decision numbers to `decisions.md`.

## Working agreement

- A checkpoint is done when its "Done when" list passes in the real app, not only in tests.
- Every checkpoint updates `animation-rules.md` so an agent can use what was built.
- Every functional decision made along the way is logged in `decisions.md` with its status.
- Anything not in the current checkpoint is written in the backlog, not built.
- Basic interactions get a feel pass before the checkpoint closes: latency, feedback, discoverability, and what an accidental click does.

In: path drawing in the preview with corners and curves, smoothing, and cleanup (R70; corners, drawing, and point editing came early, D194); the path animation with easing, orientation, and timed checkpoints (R71; it is the `path` verb with a shape, D192); points editable in the preview and the code, and objects attached to another's path (R72, R14; a path is an animation, not an object, D192); morph between the core shape kinds and their dimensions (R68, D43).

Done when: a path drawn in a few clicks looks smooth, an object follows it with no visible kinks, checkpoints can be timed from the timeline and the preview, and a circle morphs into a rectangle without a visible seam.

Status 2026-10-18: the path items are built (D192 to D209, D223, D225). Left: morph, and with it the custom shapes the owner asked for next, which the requirements had kept out of scope as "freehand vector drawing and morphing" and the backlog as "drawn vector shapes"; the owner's word moves them in here. Defined 2026-10-18 for the owner's word before any is built:

- **The Shape class.** Meaning: one more kind beside Rect, Circle, and Text: `Shape({ x, y, points: [[x, y], ...], closed, smooth, fill, stroke, strokeWidth })`. Its points are in its own space, around its `x, y`, so it moves, turns, scales, groups, and collides as any object; `closed` (default true) fills it, false draws an open line; `smooth` is the curve through its points that paths have (D199); `stroke` and `strokeWidth` draw its outline, default none, so a Shape with a stroke and no fill is a line. The resize handles scale its points about the anchor and write them, as a Rect's handles write its width and height; Alt keeps the proportions. Requires: the class in the registry, with a `points` attribute type; the renderer filling the polygon, drawing the stroke, and hit-testing it; the outline for collision and the box for groups and snapping; the Selected pane row and ghost lines; completions. Medium. The alternative is two kinds, Polygon and Line, as R50 lists; one kind with `closed` is less to learn.
- **Drawing and editing a Shape.** Meaning: the Object tool gets Shape: click for corners, drag for a curve kept as its corners with `smooth` on, as the Path tool draws (D194, D199); click the first point or press Enter to close, Escape to leave it open. A selected Shape shows its points as handles in the Select tool and they edit as a path's do: drag one or several, Ctrl + click to pick, a box on empty space to pick, Delete, click the outline to add a point, right-click for Smooth curve, Straight lines, Close, Open (D194, D198). Requires: the drawing gesture on the Object tool, the handle and point machinery pointed at an object's `points` instead of a path's `shape`, the menu items. Small to medium, since the machinery exists.
- **Shapes from the kinds, and from formulas.** Meaning: right-click a Rect or a Circle for Convert to shape, which writes a Shape with the same look, its corners or a smooth circle of points, keeping the name, position, fill, and animations that still apply; sizes it animated get a note. And four generators the scene code may call, `rect(width, height)`, `circle(radius)`, `polygon(sides, radius)`, `star(points, outer, inner)`, each giving points, so a shape or a morph target is a word rather than a list; a generated list shows the ƒ mark and the code pane edits it, Convert writes literals. Requires: the operation, the generators in the evaluator, their completions. Small.
- **Morph (R68, D43).** Meaning: a Shape's verb: `blob.morph({ points: [[...]] | rect(200, 120) | () => star.points, duration: 1 })` takes its outline to the target's over the span with the usual timing and easing, and holds it after, like any animation. The outlines are each sampled along their length to one count, the start of the target's is turned to the place that moves the points least, so a circle becomes a rectangle without a seam, and each point travels straight; `closed` and `smooth` are the target's from the end. In the GUI: a clip in its own color; Selected pane rows for the target, as code and as a count; Add on a Shape offers Morph, which starts from the shape's own points so the handles then shape the end, as a move's end is dragged (D157); with a morph selected, dragging a point edits the target. A circle into a rectangle is Convert to shape, then Morph to `rect(200, 120)`: kinds stay what they are, only outlines change, so the model keeps one class per object. Requires: `points` as an attribute type the sampler interpolates, the verb, its color, the resampling, the handle edits writing the target, docs. Medium.
- **Shape presets.** Meaning: Triangle, Star, Arrow, and Line among the object presets, as Shapes; the user's own Shapes save as presets already (D227). Small.
- **Order.** The class, drawing, and editing first, then morph, then the presets; link actions (R65) and the linked-value chip stay as the small CP3 batch after, since neither blocks this.
